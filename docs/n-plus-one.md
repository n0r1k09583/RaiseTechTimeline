# N+1問題（コメント・いいね実装時）

投稿一覧を出したあと、**各投稿ごとに** コメント数・いいね数を取りに行くと遅くなる。これを **N+1問題** という。

## 何が起きるか

1. 親（投稿）を 1 回のクエリで取る … 1 回
2. 投稿が N 件あるので、子を N 回取る … N 回（いいねとコメントなら 2N 回）

タイムライン 50 件なら、件数のためだけで 100 回の追加クエリになる。

## このアプリで起きやすい場所

- タイムラインのカードに出す **いいね数** と **コメント数**
- フォロー中タイムラインで、フォロー先を 1 人ずつ問い合わせる

## 対処

1. **一括（JOIN / サブクエリ）**  
   投稿の SELECT に `like_count` と `comment_count` を乗せる。
2. **バッチ**  
   投稿 ID の配列で `WHERE post_id IN (...)` し、`GROUP BY post_id` する。

実装メモ: `backend/src/n-plus-one.example.ts`
