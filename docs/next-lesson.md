## コードレビューで出たこと（MyBatis）

**複数行の SQL を Java のアノテーション（`@Select` など）に書かない。XML に分ける。**

投稿一覧は条件が多い（タブ、`before*`、`after*`、件数サブクエリ）。これをインターフェースに `@Select(""" ... """)` で書くと、レビューしづらく、SQL の変更のたびに Java を触ることになる。

いまの分け方（この方針を続ける）:

| 役割 | 場所 |
|------|------|
| メソッド名だけ | `mapper/*.java`（`@Mapper`。SQL は書かない） |
| SQL をまとめる | `resources/mapper/*.xml`（`<sql>` で SELECT を共有） |
| 読み込み設定 | `application.yml` の `mybatis.mapper-locations` と `type-aliases-package` |

いいね・フォロー・プロフィールを足すときも同じ。`LikeMapper.xml`、`FollowMapper.xml` を新規に作り、複数行 SQL は XML 側に置く。

## プロフィール画像で苦戦したこと（率直）

プロフィール画像そのものはまだ無い。**投稿画像**で次が分かった。次回のプロフィール画像でも同じ穴がある。

### 1. ファイル選択ダイアログ

OS の「ファイルを開く」は、ブラウザ自動化やエージェントからは押しにくい。Cursor のブラウザは iframe 外しか触れず、ネイティブのファイルダイアログは操作対象にならない。確認は **人がファイルを選ぶ**か、API に multipart を直接送る。

### 2. Chrome DevTools の制限

DevTools / CDP では cookie・ダウンロード・ファイル入力など、ファイルシステムに触る系統が拒否されることがある。画像の動作確認を DevTools の Input やファイル API だけで完結させない。画面の `<input type="file">` と、サーバーの `POST` を分けて見る。

### 3. 画像アップロードのバグになりやすい点

- バックエンド（8080）が止まっていると、画面は HTML の 500 を JSON と勘違いして「リクエストに失敗しました」とだけ出す。画像以前に API 起動を確認する
- ブラウザが付ける `Content-Type` が空や `application/octet-stream` だと、JPEG でも弾く。拡張子だけに頼らないが、空タイプは分かりやすい日本語で返す
- 実体は `uploads/`、DB にはファイル名だけ。削除時はパス区切りを無視してファイル名だけ消す（ディレクトリトラバーサル）
- Vite は `/api` と `/uploads` を 8080 へプロキシする。画像 URL が 5173 のまま 8080 に届かないとサムネが壊れる
- 上限 5MB。超過は 413。形式は JPEG / PNG / WebP

プロフィール画像を足すときは、投稿と同じ `ImageStorage` を使い、`users` に `avatar_path`（NULL 可）を Flyway で足す。

## 次回の実装の方向（プロフィールとフォロー）

### フォロー・フォロワーの仕組み

`follows` は片方向の1行。`follower_id` = した人、`followee_id` = された人。相互は2行。自分自身は不可（CHECK またはサービスで 400）。

```
UNIQUE (follower_id, followee_id)
```

| 操作 | SQL の意味 | 画面 |
|------|------------|------|
| フォローする | INSERT 1行 | ボタンが「フォロー中」。相手のフォロワー数が +1 |
| 解除する | その行を DELETE | ボタンが「フォロー」。件数 -1。「フォロー中」タブから相手の投稿が消える |
| フォロー n | `COUNT(*) WHERE follower_id = その人` | プロフィール。押すと一覧 S-06 |
| フォロワー n | `COUNT(*) WHERE followee_id = その人` | 同上 |
| 自分がフォロー中か | 自分→その人の行があるか | `followed_by_me`。ボタンの見た目 |

「フォロー中」タイムラインは、フォロー先を1人ずつ取らない。1回のクエリで:

```sql
AND (p.user_id = #{viewerId}
  OR p.user_id IN (SELECT followee_id FROM follows WHERE follower_id = #{viewerId}))
```

シードの意図: 花子が山田をフォロー。一郎は誰もフォローしない。

### プロフィール画面でのフォロー状態

画面は S-05（`/users/:username`）。

| 見る人 | 出すもの |
|--------|----------|
| 他人 | 「フォロー」または「フォロー中」（トグル）。フォロー n・フォロワー n。その人の投稿 |
| 自分 | フォローボタンは出さない。「プロフィールを編集」。件数と自分の投稿 |

ヘッダーの表示名 → 自分のプロフィール。投稿・コメントの `@ユーザー名` → その人のプロフィール。検索（F-07）はプロフィールのあとでもよいが、入口はユーザー名クリックだけでもフォローの検証はできる。

プロフィール編集（次回）: 表示名・自己紹介・プロフィール画像。ユーザー名の変更は一意制約があるので、最初は表示名と画像だけでもよい。
