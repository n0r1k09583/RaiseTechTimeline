# RaiseTechタイムライン

X（旧Twitter）風の **テキストベースSNS**（学習用）。受講生や個人が、複数アカウントで投稿・コメント・いいね・フォローし合う。

いまは **認証・投稿・コメント** まで。いいね操作・フォロー・検索は次。ログイン後はタイムライン。自分の投稿は直後に反映し、続きは無限スクロール、他人の更新は約30秒おきに静かに取り直す。コメント数は投稿一覧の同じ SELECT で取る（N+1 にしない。[docs/n-plus-one.md](docs/n-plus-one.md)）。開発開始後に足した判断は [docs/dev-changes.md](docs/dev-changes.md)。

必要なもの: **Java 21**、**Node.js**（npm）。Maven のインストールは不要（`backend/mvnw` を使う）。`.env` は無くても起動する。

### Webアプリ（提出先でも同じ手順）

クローンしたリポジトリの中で実行する。自分の PC の絶対パスは書かない。**必ず各フォルダに入ってから**起動する（リポジトリ直下の `mvn` では SQLite の場所がずれる）。

ターミナル1（API。先に起動）:

```powershell
cd backend
.\mvnw.cmd -Dmaven.test.skip=true spring-boot:run
```

macOS / Linux:

```bash
cd backend
./mvnw -Dmaven.test.skip=true spring-boot:run
```

ターミナル2（画面）:

```powershell
cd frontend
npm install
npm run dev
```

ブラウザ: **http://127.0.0.1:5173**（5173 が使われていたら止めてから再実行。勝手に 5174 にはしない）  
API: http://127.0.0.1:8080/api/health

試すアカウント（パスワードはすべて `password123`）: `yamada@example.com` / `hanako@example.com` / `ichiro@example.com`

起動に失敗したら、`backend/data/timeline.db` を消して API をもう一度起動する（空の DB なら Flyway とデモユーザーが入る）。`.env` は任意。秘密鍵を Git に書かない。

## 何をするアプリか

初級編の最終課題「おうち受付」は、受付担当と来客の **お問い合わせアプリ** だった。中級編の3つ目のアプリとして、利用者同士が同じ立場でやり取りするSNSに入る。

- 全員が見えるタイムライン「すべて」と、フォローした人だけの「フォロー中」
- 第三者のいいね・コメントの件数を、詳細を開かなくても一覧で出す
- ユーザー名で検索し、投稿・コメントのユーザー名からプロフィールへ進んでフォローできる

管理者ロールは作らない。全員が同じ権限の利用者である。

## 機能（要件定義・機能定義書に基づく）

機能定義書は `docs/FEATURES/機能定義書.md`（Functional Requirements）。ディレクトリ名は **FEATURES** であり、`FUTURES`（将来拡張）ではない。

| ID | 機能 | 内容 |
|----|------|------|
| F-01 | ログイン | 新規登録・ログイン・ログアウト。メール＋パスワード。ユーザー名は一意 |
| F-02 | タイムライン | 投稿作成。「すべて」／「フォロー中」。いいね数・コメント数をカード上に出す |
| F-03 | コメント | 第三者もコメント可。件数表示。コメントのユーザー名をクリックするとプロフィールへ |
| F-04 | いいね | 第三者もいいね可。1人1投稿につき1回。件数表示 |
| F-05 | 画像投稿 | 1投稿あたり任意で画像1枚（JPEG / PNG / WebP、5MBまで） |
| F-06 | フォロー | 他ユーザーのフォロー／解除。自分はフォロー不可。フォロー数・フォロワー数 |
| F-07 | ユーザー検索 | ユーザー名の部分一致検索。結果からプロフィールへ進みフォローできる |

### 今回作らないもの

ハッシュタグ検索、リポスト、引用、ブックマーク、DM、動画・複数枚画像、管理者画面、通報、パスワード再設定メール、アプリの本番公開（常時稼働のURL）、WebSocket で投稿のたびに全員へ通知すること。

## 技術スタック

にゃんこタスク（`Trello風タスクアプリ`）のロックファイルに合わせる。おうち受付の Next.js / Express には戻さない。

| パッケージ | 使うバージョン |
|------------|----------------|
| react / react-dom | 19.2.8 |
| vite | 6.4.3 |
| typescript | 5.7.3 |
| @vitejs/plugin-react | 4.7.0 |
| @types/react | 19.2.17 |
| @types/react-dom | 19.2.3 |

`@dnd-kit` はタスクボード用なので、このSNSには入れない。

にゃんこタスクは一人用で localStorage だった。このSNSは複数人が同じ投稿を見るため、実装時に共有できる保存を足す。画面の React / Vite / TypeScript のバージョンは変えない。

AWS は無料枠の範囲で後から触れる。常時稼働の本番URLは作らない。NAT Gateway / 有料 RDS / ALB は使わない。

## 使い方（実装後の操作）

| やりたいこと | 操作 |
|--------------|------|
| アカウント作成 | ログイン画面 → 新規登録（ユーザー名・表示名・メール・パスワード） |
| 投稿 | タイムライン上部に本文（任意で画像）→ 投稿する |
| タイムライン切替 | 「すべて」／「フォロー中」 |
| いいね | ハート。もう一度押すと取り消し |
| コメント | 投稿の「コメント n件」→ 詳細で送信 |
| プロフィール | 投稿・コメントのユーザー名をクリック |
| フォロー | 他人のプロフィールの「フォロー」 |
| ユーザー検索 | ヘッダーの検索欄にユーザー名 |

受け入れの目安（A・B・Cの3アカウント）:

1. Aが投稿する
2. Bが同じタイムラインで見ていいねする（件数が増える）
3. Cがコメントする（コメント件数が増える）
4. BがAをフォローする（「フォロー中」にAの投稿が出る）
5. Cがユーザー名検索、またはコメントのユーザー名からプロフィールへ進んでフォローできる

デモユーザー例: 山田（@yamada）、佐藤（@hanako）、鈴木（@ichiro）。

## スキル（タスクマネジメントからの転用）

タスク管理プロジェクトに `.cloud` フォルダは無かった。スキルは `.cursor/skills` にあったので、そこを転用している。

| 場所 | 内容 |
|------|------|
| `.cursor/skills/neko-task-board/` | にゃんこタスクの Skill をそのままコピー |
| `.cursor/skills/raisetech-timeline/` | 本SNS用。要件・FEATURES・バージョンを正とする |
| `.vscode/` | タスク管理側のエディタ設定を転用 |

PowerShell の `.ps1` に日本語を直書きしない、など、転用した Skill の注意は実装時も守る。
